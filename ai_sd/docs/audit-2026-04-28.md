# ai_sd Audit — 2026-04-28

Scope: gap analysis vs. xororz/local-dream commits Apr 19-24 2026, plus an independent
quality pass on the SDK as it stands today.

## How the system works

Generation flow (single image):

1. **JNI entry** — `nativeGenerate` (`ai_sd_jni.cpp:181`) acquires a `shared_lock`,
   pins to ARM big cores, calls `g_sd_state.generate()` → `sd_pipeline::run_generation()`.
2. **CLIP encode** — `text_encoder` tokenises prompt + negative prompt, runs CLIP twice
   (neg, then pos), returns `text_embedding[2×77×768]`. MNN CLIP interpreter is released
   immediately after to drop peak memory (`pipeline_orchestrator.cpp:~227`).
3. **Scheduler init** — `scheduler_factory.h` returns DPM++ or Euler-A. **LCM is not
   implemented** even though the API advertises it.
4. **(Optional) VAE encode** for img2img — input RGB → latent.
5. **UNet loop** — for each timestep, two passes (uncond + cond); CFG combiner
   `uc + cfg*(tx-uc)` runs as a plain float loop. **Both passes always run**, even at
   cfg=1.
6. **VAE decode** — latent → NCHW float → RGB uint8.
7. **(Optional) Safety check** — NSFW classifier on the final image.
8. **Callback** — `on_complete()` → Kotlin builds `Bitmap`.

Concurrency: a `shared_lock` allows multiple `generate()` calls if no `load_models()` is
running. Kotlin serialises callers via `compareAndSet(_isGenerating)`, so practically a
single generation runs at a time. Many globals in `pipeline_orchestrator.cpp` are
written per-generation — safe only because Kotlin enforces serialisation.

## Independent findings

### A. `generateImageSync()` silently drops img2img (HIGH)
`DiffusionManager.kt:397-414` hardcodes `inputImage = null, mask = null` in the
`nativeGenerate()` call even though `params.inputImage` / `params.mask` are present on
the input. The async overload passes them; sync silently broken.

### B. `nativeRelease` skips secondary modules (MEDIUM)
`ai_sd_jni.cpp:317-325` calls `g_sd_state.release()` and `sd_jni::reset_cache()` but
not `g_segmenter.reset()`, `g_lama_inpainter.reset()`, `g_depth_estimator.reset()`,
`g_style_transfer.reset()`. Each module has its own `release_*` JNI but no master
cleanup path → memory leaks across model swaps.

### C. Partial-load globals not rolled back (MEDIUM)
`model_loader.cpp::initialize_models()` mutates `clipPath`, `unetPath`, etc. before
attempting any load. If load fails partway (CLIP ok, UNet not), globals retain stale
values. Subsequent `generateImage` may pass the `!unetApp` guard but find stale
`prompt`/`steps`/`cfg`. No commit-or-rollback.

### D. Mask byte-array bounds not validated (MEDIUM)
`ai_sd_jni.cpp:226-254` indexes mask as latent-space (`(width/8) * (height/8) * 3`).
A caller passing a full-resolution mask produces a wrong sample with no error.

### E. `clip_v2` detection by raw substr (LOW)
`model_loader.cpp:263-265` compares `clipPath.substr(len-8) == "clip.mnn"`. A custom
name like `myclip.mnn` falsely triggers the v2 sibling lookup. Use
`std::filesystem::path(clipPath).filename() == "clip.mnn"`.

### F. TI loader doesn't filter LoRA `.safetensors` (LOW)
`prompt_processor.h:244` iterates every `.safetensors` in the embeddings dir — drops
a LoRA file in there, it tries to load it as a TI embedding (`tensor_names[0]` is a
LoRA weight key) → garbage embedding, no error.

### G. Upscaler QNN globals not freed by `nativeReleaseUpscaler` (LOW)
The QNN `upscalerApp` global (`pipeline_orchestrator.cpp:139`) is not reset by
`nativeReleaseUpscaler` (`ai_sd_jni.cpp:471-478`). MNN path is fine — it uses a local
shared_ptr that goes out of scope after the call.

## Recommended fix order

1. **Finding A** — one-line fix, restores documented img2img sync API.
2. **Gap #8 (upscaler 2048 cap)** — single guard, prevents OOM crash on camera-resolution input.
3. **Gap #1 (skip uncond on cfg=1)** — small C++ change, ~2× speedup whenever a user runs with cfg=1.
4. **Gap #6 (TI dimension filter)** — prevents silent quality degradation when mixing model families.
5. **Finding B** — add the missing `reset()` calls inside `nativeRelease`.
6. **Gap #2 (CLIP cache)** — high payoff for re-roll workflows; medium complexity.
7. **Gap #3 (LCM scheduler)** — implement to deliver the API surface that's already advertised.
8. **Gap #4 (SoC table)** — needed before any SDXL story makes sense.

## Out of scope today

- True two-encoder **SDXL** support (gap #5 + parts of #4) — significant new code path; defer.
- Reference-app UI features (gaps #7, #9, #10) — not applicable to a library.
