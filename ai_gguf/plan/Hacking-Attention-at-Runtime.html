00 The Intervention Map theory
If you control the source, every line of the attention forward pass is a potential intervention point. The standard attention equation is Attn(Q,K,V) = softmax( Q·Kᵀ / √dₖ + M ) · V, but each component of that equation can be intercepted and altered. There are six distinct intervention surfaces: the QKV projections, the raw scores, the mask M, the softmax function itself, the values, and the KV cache. Each targets a different aspect of model behavior.

01 Score Injection & Bias lab + prod
The most direct intervention: add a bias matrix B to the attention scores before softmax. The full equation becomes: softmax( (Q·Kᵀ / √dₖ) + B + M ). Since B is added pre-softmax, each entry B[i,j] exponentially amplifies or suppresses the attention from token i to token j. A value of +5 ≈ 148× more likely to attend; -∞ = complete block.

This is how ALiBi (Attention with Linear Biases) encodes relative position, how attention sinks are forcibly maintained, and how you can surgically amplify a model's focus on specific tokens (e.g., the system prompt, a retrieved document).
Interactive — Drag the bias sliders for any token pair
B_alibi[i,j] = −m · |i − j|    where m = 2^(−8/h) per head
ALiBi (Press et al. 2021) eliminates positional encodings entirely. Instead, it adds a static, non-learned bias to each score equal to negative distance between tokens, scaled per head. Head 1 uses slope m₁ ≈ 0.5, head 2 uses m₂ ≈ 0.25, etc.

Effect: Each head has a different "attention horizon" — some heads focus locally (steep slope), some globally (shallow slope). No parameters added.

Runtime power: If you control source, you can change these slopes dynamically. Increase all slopes → make the model more local (useful for tasks that need nearby context). Decrease slopes → make it more global. You can even make slopes negative (inverted distance bias) to make tokens attend to tokens far away. Used in MPT-7B, BLOOM.
Score Clamping: Before softmax, you can clamp attention scores to a range [−c, +c]. This prevents any single token from dominating attention with extremely high scores — a known failure mode where models fixate on one token ("attention collapse").

scores = torch.clamp(scores, min=-50.0, max=50.0)

More surgical version: score quantile filtering — zero out scores in the bottom p-th percentile per row. This forces the model to distribute attention more broadly, reducing overconfidence. Useful when you observe attention collapse in long generations.
Importance: the softmax temperature. Dividing scores by a constant T before softmax controls sharpness:

T < 1 → sharper, more peaked distribution → model is more "confident" in what to attend to
T > 1 → flatter, more uniform → model attends more broadly, less focused

This is the attention analog of output temperature. You can apply different T per layer, per head. Early layers often benefit from flatter attention (building broad context), later layers from sharper (extracting specific patterns).
Sun et al. (2024) — Learnable KV Bias: Instead of modifying scores, inject learned bias vectors directly into the Key and Value projections:

K_biased = K + b_k # b_k is a learned [1 × d_head] bias
V_biased = V + b_v # shared across all tokens

This creates a "default" Key that every query can always attend to — effectively an always-present sink token. Used to combat attention sink instability and reduce quantization outliers in activations. Adopted in OpenAI's open-weight models to enable aggressive INT4 quantization.

02 Sparse Attention Patterns prod
Full attention computes N² pairs — for N=8192 tokens, that's 67M entries. Sparse attention restricts which pairs are computed by setting most of the mask M to −∞. Different sparsity patterns balance local context (nearby tokens) vs global context (all-to-all).

You implement this as a custom mask passed into your attention kernel. At source level, you're just changing what goes into M before softmax — but the kernel implementation determines whether you actually skip the computation (true sparse) or just mask it (still O(N²) compute). True sparsity requires custom CUDA kernels like FlashAttention with block sparsity.
Click a pattern — see the mask matrix (dark = attended, grey = blocked)
Longformer (Beltagy et al. 2020) combines three attention patterns:

1. Sliding window: Each token attends to w/2 tokens on each side. O(n·w) complexity.
2. Dilated sliding window: The window has gaps — attends to every d-th token. Covers longer range at same cost. Higher layers use larger dilation.
3. Global tokens: Designated tokens (e.g., [CLS], task-specific question tokens) attend to all others AND are attended to by all. Full-cost but controllable.

Runtime power: You decide which tokens get "global" attention. For document QA, make the question tokens global at inference time. For summarization, make the first sentence global. This is pure mask surgery — change M, not weights.
BigBird (Zaheer et al. 2020) adds a fourth element: random attention. Each token attends to r randomly chosen tokens, independent of position. Graph theory shows that random sparse connections are nearly as expressive as full attention for modeling long-range dependencies (a sparse graph with random edges has short path lengths between any two nodes).

At runtime, you can change the random seed per layer — different heads see different random connection patterns. This is structurally interesting: the model was never trained with a specific random pattern, yet performance is robust because the math holds for any random sparse graph.
MInference (Microsoft, 2025): The key insight is that attention patterns in trained LLMs are not uniformly sparse — they have three recurring shapes:

• A-shape: Heavy on first few tokens + recent window (like StreamingLLM)
• Vertical-slash: Consistently high attention to specific token columns
• Block-diagonal: Dense within contiguous chunks, sparse elsewhere

MInference detects which pattern each head uses at runtime (one forward pass on a calibration prompt), then applies the matching sparse kernel. No training. For 1M token contexts, achieves 10× speedup with less than 1% accuracy loss. This is production-ready inference-time sparsity.

03 Attention Sinks & StreamingLLM discovered phenomenon
Xiao et al. (MIT, 2023) discovered something strange: every layer in a trained LLM dumps large amounts of attention on the first 1–4 tokens — regardless of whether those tokens are semantically relevant. These are "attention sinks." Why? Softmax forces attention weights to sum to 1. When no token is contextually relevant, the model needs somewhere to "park" the unused probability mass. The first few tokens serve as this garbage collector.

Consequence: If you evict those first few tokens from the KV cache (to save memory), the model produces complete gibberish. The fix: keep them always, even if old. This single insight unlocked infinite-length generation.
Attention Sink Pattern — token 0 absorbs excess weight regardless of content
step 0
KV_cache = [sink_tokens(4)] + [recent_window(N-4)]
StreamingLLM: Permanently keep 4 sink tokens in KV cache. Slide a window of recent tokens. Discard the middle. Result: constant memory regardless of generation length, stable text output even at 4M+ tokens.

Implementation is 3 lines of code change in your attention forward pass. Integrated in HuggingFace, NVIDIA TensorRT-LLM, and deployed on iPhone via Core ML. Also compatible with GQA/MQA models.

Limitation: The model can only reference the last N tokens and the 4 sink tokens. Long-range factual recall fails. Good for: chat assistants, streaming generation. Bad for: document comprehension, long-form reasoning.
# Standard attention kv_cache = past_kv # shape: [layers, 2, batch, heads, seq, d_head] # StreamingLLM modification — just change how you build the cache def update_kv_streaming(cache, new_k, new_v, sink_size=4, window=2048): sink_k = cache[:sink_size] # always keep first 4 sink_v = cache[:sink_size] recent_k = cache[sink_size:][-(window-sink_size):] # sliding window recent_v = cache[sink_size:][-(window-sink_size):] return torch.cat([sink_k, recent_k, new_k], dim=-2)
Why sinks form — the variance explanation:

Softmax is non-permutation-invariant — the first token naturally has highest variance in its key representations across training data (it's always present, always varied in meaning: sometimes it's BOS, sometimes a content word, sometimes punctuation).

After softmax normalization, tokens with high key variance attract more attention weight. The first token's KV accumulates this property over training. It becomes a "computational buffer" — when the model's query doesn't strongly match anything, it defaults to the high-variance first-token key.

Implication: You can design a dedicated sink token — a special [SINK] token prepended to every input, given a deliberately high-variance key initialization. The model learns to use it as a sink from the first training steps. GPT-4 reportedly does this.
Learnable Sink Tokens (Sun et al., 2024):

Instead of using actual input tokens as sinks, add learnable KV bias vectors that are always present in the attention:

K_full = [b_sink_k(trainable)] + K # prepend learnable key
V_full = [b_sink_v(trainable)] + V # prepend learnable value

Only ~2 × d_head parameters (≈128 floats for d_head=64). The learnable sink key adjusts during fine-tuning to absorb exactly the activation outliers in that model. Side effect: dramatically reduces activation outliers, making INT4 quantization stable. This is why OpenAI's open-weight models can be quantized so aggressively.

04 KV Head Compression: MHA → MQA → GQA → MLA production
In standard MHA with h=32 heads and d_k=128, the KV cache stores 2 × 32 × 128 = 8192 floats per token per layer. For a 32-layer model at 100K tokens: 100K × 32 × 8192 × 2 bytes = 52 GB just for KV cache. That's why MQA, GQA, and MLA exist — they change the structure of who shares keys and values.

You have source-level control over this: `num_kv_heads` is a hyperparameter in your attention module. You can change how many distinct KV groups exist without changing Q heads or model dimension.
Click to see KV head sharing — Query heads (top) sharing Key/Value heads (bottom)
MHA cache: 2 · h · d_k · L · N bytes
GQA cache: 2 · g · d_k · L · N bytes (g << h)
MQA cache: 2 · 1 · d_k · L · N bytes
For Llama-3-70B: h=64, g=8, d_k=128, L=80 layers, N=1000 tokens:

MHA: 2×64×128×80×1000 × 2 bytes = ~2.6 GB per 1K tokens
GQA (g=8): ÷8 = ~325 MB per 1K tokens

This is why Llama-3-70B can serve longer contexts in production — GQA was specifically chosen for memory budget reasons, not accuracy. The accuracy difference between MHA and GQA (g≥4) is typically less than 1% on standard benchmarks.
# GQA forward — the key code in repeat_kv def repeat_kv(x, n_rep): # x: [batch, seq, n_kv_heads, head_dim] if n_rep == 1: return x bs, slen, n_kv, hd = x.shape return (x[:, :, :, None, :] .expand(bs, slen, n_kv, n_rep, hd) .reshape(bs, slen, n_kv * n_rep, hd)) # In attention forward: n_rep = self.n_heads // self.n_kv_heads # e.g. 64//8 = 8 K = repeat_kv(K, n_rep) # broadcast K to all query heads V = repeat_kv(V, n_rep) # broadcast V to all query heads
Multi-head Latent Attention (DeepSeek-V2, 2024):

Instead of reducing K/V heads, MLA compresses the K and V tensors themselves into a low-rank latent:

c_kv = x @ W_kv_down # compress: [seq, d_model] → [seq, r] where r << d_model
K = c_kv @ W_k_up # expand back to key space per head
V = c_kv @ W_v_up # expand back to value space per head

Store only c_kv in cache (r floats) instead of full K,V (2×h×d_k floats). For DeepSeek-V2: r=512, h×d_k=128×128=16384. Cache reduction: 32× with higher expressiveness than GQA. The "absorb" trick fuses W_k_up into Q projection at inference time, eliminating the expand step entirely.
Converting MHA → GQA post-training (no full retrain):

You don't always need to retrain from scratch. The GQA paper showed you can convert an existing MHA model:

1. Group the h KV heads into g groups (e.g., h=32 → g=8)
2. For each group, mean-pool the h/g KV head weights: W_k_group = mean(W_k_i for i in group)
3. Fine-tune with ~5% of original compute budget to recover quality

This is used in production to create faster MQA/GQA inference versions of models originally trained with MHA. Works because nearby heads in the original model often learn correlated representations.

05 KV Cache Pruning at Runtime prod + lab
Rather than changing model architecture, you dynamically evict tokens from the KV cache during inference based on how much attention they've received. The premise: tokens that have been attended to frequently are "important" and should stay; tokens consistently ignored can be dropped.

This is pure runtime logic — your attention forward pass looks the same, but you decide which past KV entries to retain at each decoding step. The model never "knows" anything was dropped — it just has a shorter KV sequence.
KV Eviction Strategies — click to compare (N=12 tokens, budget=6)
H2O — Heavy-Hitter Oracle (Zhang et al. 2024): Tracks cumulative attention scores for each token across all heads and layers. At each step, the "heavy hitters" — tokens with highest accumulated attention — are retained. The bottom (budget - heavy_hitters) are evicted.

scores_accum += attn_weights.sum(dim=0) # accumulate per-token
keep_idx = scores_accum.topk(budget).indices # keep top-k
K_cache = K_cache[keep_idx]
V_cache = V_cache[keep_idx]

Achieves ~4× KV cache compression with less than 5% accuracy loss on most benchmarks. The key insight: a small fraction of tokens consistently attract most attention ("heavy hitters") across diverse inputs.
SnapKV (Li et al. 2024): A more structured approach for long-prompt inference. Observes that attention patterns stabilize after the prompt is processed. So:

1. Process the full prompt once (prefill phase)
2. Look at attention scores of the last few tokens of the prompt — these reveal which tokens the model deems important
3. Keep only those important prompt tokens in the KV cache + full recent window
4. Decode autoregressively with compressed prefix

Advantage over H2O: The selection is done once, not updated every step — cheaper. Disadvantage: assumes the important tokens for the query are visible from prompt-end attention. Works well for QA, RAG; less so for creative generation.
KIVI — KV Cache Quantization: Instead of dropping tokens, quantize their stored KV vectors to INT2 or INT4. This is a different dimension of compression.

Key observation: K vectors tolerate lower precision than V vectors (V affects output directly; K only affects routing). KIVI uses INT2 for K and INT4 for V, keeping the last few tokens in FP16 (recent tokens are used more and need precision).

Practically: 4× memory reduction with under 1% quality loss on Llama. Combined with GQA, you can get 8–16× KV cache reduction. This is how you fit 128K context windows on consumer hardware.

06 Activation Steering Through Attention lab-grade
The most powerful runtime intervention: add a steering vector to the residual stream at specific layers. Because multi-head attention outputs are added to the residual stream (the "highway"), you can intercept this and inject a directional vector that biases what the attention represents.

The technique (Zou et al. 2023, Anthropic 2023): run the model on contrastive pairs (formal vs informal, factual vs hallucinating), extract the mean difference of residual stream activations at a target layer, then add α× that difference at runtime. Called Representation Engineering — you're steering the model's internal representations, not its outputs.
Steering Vector Effect — Vary α to see the conceptual shift
0
Step 1 — Build contrastive dataset: ~20–100 pairs of prompts representing the contrast you want. Example for "formal vs casual": "Please write a business proposal" vs "hey write me a pitch".

Step 2 — Extract activations: Run both sets through the model. For each layer, record the mean residual stream activation at the last token position.

hooks = [] residuals = {} def hook_fn(layer_idx): def h(module, input, output): residuals[layer_idx] = output[0].detach() # residual stream return h for i, layer in enumerate(model.layers): hooks.append(layer.register_forward_hook(hook_fn(i)))

Step 3 — Compute vector: steering_vec[layer] = mean(pos_acts) − mean(neg_acts)

Step 4 — Inject: At inference, after each target layer's attention + FFN, add: hidden_states += α × steering_vec[layer]
Head-Level Steering (UniBias, NeurIPS 2024): Instead of steering the full residual stream, identify which specific heads contribute to biased behavior, then zero or scale their outputs.

For each head h in layer l, compute: head_importance[l,h] = |contribution to biased token| × |frequency of activation|

At inference: for heads above importance threshold, multiply their output by (1 − suppress_factor). For heads below threshold, leave intact. This is more surgical than full activation steering — you preserve the neutral heads while suppressing the biased ones.

Used in production for: debiasing models toward specific labels, suppressing hallucination-prone heads, enforcing style consistency.
Honest limitations of activation steering:

1. Entanglement: Representation directions are rarely clean. "Formal tone" direction likely correlates with "financial domain" and "legal language" — you may get unintended side effects.

2. Coherence degradation: High α values produce incoherent text. There's a practical ceiling around α=15–20 beyond which outputs fall apart.

3. Layer sensitivity: The right layer varies by concept. Lower layers = surface style. Middle layers = factual content. Upper layers = task-specific behavior. Finding the right layer requires empirical search.

4. Transfer across models: Vectors found in Llama-3-8B rarely transfer well to Mistral-7B, even if architecturally similar. Representations are not standardized.

07 Replacing Softmax: Sigmoid, Linear & Beyond lab-grade
The softmax is a bottleneck: it forces all attention weights to sum to 1, creating token competition. Every token "takes" probability mass from others. This is why attention sinks exist, why increasing context length hurts focus, and why the model can't attend to two unrelated things simultaneously with equal strength.

You can replace softmax entirely in the forward pass with different normalizations. Each changes the semantics of what attention means — from "distribution over tokens" to "independent relevance score per token."
Normalization Comparison — Same scores, different functions
1.5×
Attn_sigmoid(Q,K,V) = sigmoid(Q·Kᵀ / √dₖ + b) · V
Sigmoid attention (SWAT paper, 2025): Replace softmax with sigmoid applied independently to each score. No competition between tokens. The bias b = −log(n) keeps values calibrated for sequence length n.

Advantages:
• No attention sink: Softmax needed sinks because weights must sum to 1. Sigmoid has no such constraint — it doesn't need to "dump" unused probability anywhere.
• Monotone: Adding new tokens can't reduce attention to existing tokens (softmax competition shrinks all weights when new tokens enter).
• Better for sliding window: Works stably when window drops old tokens, because there's no renormalization artifact.

Disadvantage: Output scale grows with n (sum of sigmoids can exceed 1). Need to divide by sequence length or use a learned scaling factor.
Linear Attention: Replace softmax(QKᵀ) with a kernel function φ(Q)φ(K)ᵀ where φ is an element-wise feature map (e.g., ELU(x)+1 or ReLU(x)). This allows the associativity trick:

# Standard: O(N²d) — compute QKᵀ first (N×N matrix)
out = softmax(Q @ K.T) @ V

# Linear: O(Nd²) — compute KᵀV first (d×d matrix!)
S = (phi_K.T @ V) # [d, d] — context state
out = phi_Q @ S # [N, d] — O(Nd²) not O(N²d)

This is the key to O(N) attention. The context "state" S is a d×d matrix that summarizes all past tokens. Can be computed recurrently — making it as fast as an RNN at inference while being trainable as a Transformer.
RWKV and SSMs (Mamba): The logical endpoint of replacing softmax — eliminate the attention matrix entirely:

RWKV: Uses time-mixing (learned decay) and channel-mixing instead of QKV. The "attention" is a linear recurrence: hidden_t = w × hidden_{t-1} + u × x_t, where w and u are learned per-channel scalars. O(1) per token at inference.

Mamba (SSM): State space models with input-dependent transition matrices. The "context" is a fixed-size hidden state that gets updated recurrently. Remarkably: Mamba-3B matches Transformer-3B on many benchmarks at 5× inference speed.

Runtime modification angle: If you have a Transformer's source, you can replace specific attention layers with RWKV or SSM layers — hybrid architectures. Jamba (AI21), Zamba, and Bamba do exactly this: 60% attention layers + 40% Mamba layers, getting nearly Transformer quality at near-Mamba speed.

08 The Production Stack systems
Where these techniques live in real inference stacks. FlashAttention rewrites the attention kernel to never materialize the full N×N matrix in HBM — it tiles the computation in SRAM, reducing memory reads from O(N²) to O(N). It's transparent to the math: same outputs, radically different memory behavior.

vLLM adds PagedAttention — treating the KV cache like OS virtual memory with fixed-size pages, enabling non-contiguous token sequences and copy-on-write for beam search. TensorRT-LLM compiles all of these into fused CUDA kernels at model-build time. The techniques above sit as configuration layers on top.
Production Stack — where each technique lives
FlashAttention-3 (Dao & Shah, 2024): GPU SRAM ≈ 192KB. The N×N attention matrix at N=8192 = 268MB. FlashAttention tiles this into blocks that fit in SRAM, computing each block fully before writing results to HBM.

Implications for custom attention:
• Custom masks: FlashAttention supports custom mask functions via the FlexAttention API (PyTorch 2.5+) — you define a Python function that maps (b, h, q_idx, k_idx) → bias_value, and it gets JIT-compiled into an efficient kernel.
• Block sparsity: FlashAttention can skip entire blocks if the mask marks them as −∞. Real O(N·sparsity) compute.
• Custom score mods: Add ALiBi, RoPE, score clamping all within the kernel.
# FlexAttention — define custom score modification (PyTorch 2.5+) from torch.nn.attention.flex_attention import flex_attention, create_block_mask def sliding_window_causal(b, h, q_idx, kv_idx): # Combined: causal + sliding window of 512 causal = q_idx >= kv_idx in_window = q_idx - kv_idx <= 512 return causal & in_window def alibi_score_mod(score, b, h, q_idx, kv_idx): slope = 2 ** (-(8 / num_heads) * (h + 1)) bias = -slope * torch.abs(q_idx - kv_idx).float() return score + bias block_mask = create_block_mask(sliding_window_causal, B, H, SEQ, SEQ) out = flex_attention(Q, K, V, score_mod=alibi_score_mod, block_mask=block_mask)
FlexAttention is the cleanest API for everything discussed in this page. It exposes two hooks:

• score_mod(score, b, h, q_idx, kv_idx) → score: Modify pre-softmax scores. Use for: ALiBi, logit bias, attention sinks, score clamping, temperature per head.

• mask_mod(b, h, q_idx, kv_idx) → bool: Define sparsity pattern as a boolean function. Use for: sliding window, prefix masking, document boundaries, custom causal patterns.

PyTorch compiles both into Triton kernels automatically. You get custom attention semantics at near-FlashAttention speed. This is the recommended production path for custom attention modifications in 2025+.
