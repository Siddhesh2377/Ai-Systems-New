RESEARCH SCOPE: 8 GGUF FORMAT WEAKNESSES
================================================================================

1. ROW-MAJOR LAYOUT NOT GPU-OPTIMIZED
   Severity: HIGH | Effort: MEDIUM | Gain: 15-25%
   Problem: GGUF row-major layout doesn't match GPU cache/tiling hierarchy
   Solution: Load-time transpose to GPU-optimal layout, cache on disk
   Status: Research complete (MNN-LLM 20% gain baseline documented)

2. BLOCK QUANTIZATION ASSUMES UNIFORM IMPORTANCE
   Severity: HIGH | Effort: MEDIUM | Gain: 8-12%
   Problem: All tensor blocks quantized uniformly; attention heads vary in importance
   Solution: Use IQ2_XS/IQ3_XXS types, mixed-precision per layer
   Status: Research complete (AWQ/GPTQ papers, llama.cpp IQ types available)

3. NO CL_IMAGE2D LAYOUT
   Severity: MEDIUM | Effort: MEDIUM-HIGH | Gain: 5-15%
   Problem: GGUF lacks OpenCL image format for Adreno texture engine access
   Solution: Post-load conversion to CL_Image2D for activation tensors only
   Status: Research complete (MNN-LLM texture optimization documented)

4. 32-BYTE ALIGNMENT DOESN'T MATCH GPU CACHE LINES
   Severity: MEDIUM | Effort: LOW | Gain: 2-5%
   Problem: Mobile GPUs have 64-128 byte cache lines; 32-byte alignment causes straddling
   Solution: Use 128-byte alignment (LCM of common cache lines)
   Status: Research complete (ARM Mali 64-byte, Adreno proprietary; 128 is safe)

5. SEQUENTIAL METADATA (NO INDEX)
   Severity: LOW | Effort: VERY LOW | Gain: <1%
   Problem: Linear scan of metadata KV pairs; no hash index
   Solution: Accept current design; <100ms scan time, one-time load cost
   Status: Research complete (metadata scan is NOT bottleneck)

6. NO TENSOR DEPENDENCY INFO
   Severity: MEDIUM | Effort: MEDIUM | Gain: 5-10%
   Problem: No hints for layer prefetching; transformer layers sequential
   Solution: Heuristic prefetch using madvise(MADV_WILLNEED) on next layer
   Status: Research complete (ExecuTorch/TensorRT track dependencies similarly)

7. LARGE VOCAB EMBEDDING TENSORS
   Severity: MEDIUM | Effort: LOW | Gain: 10-15%
   Problem: Per-token embedding lookup doesn't amortize aggressive quantization
   Solution: Keep embeddings in FP16/Q8, aggressively quantize weights
   Status: Research complete (weight tying + selective quantization standard)

8. NO SPLIT-DEVICE SCHEDULING HINTS
   Severity: MEDIUM | Effort: MEDIUM | Gain: 20-35%
   Problem: No guidance for GPU/NPU/CPU split; no operator-level affinity hints
   Solution: External .sched.json config, profile-guided placement
   Status: Research complete (HeteroInfer/ExecuTorch patterns documented)
   Note: AiSystems Phase 1-2 heterogeneous backend ready for integration

================================================================================
KEY FINDINGS
================================================================================

Finding 1: GGUF Tensor Info HAS Offset Fields
  → Random access to tensor data IS possible
  → Only metadata KV pairs are sequential (not a bottleneck)

Finding 2: Importance Quantization Exists in llama.cpp
  → IQ2_XS, IQ3_XXS, IQ4_NL types available
  → No llama.cpp modifications needed; pure model conversion

Finding 3: Mobile GPU Cache Hierarchy Mostly Proprietary
  → Adreno: 10MB L3 public, L1/L2 not documented (use safe 128-byte alignment)
  → Mali: 64-byte cache line documented
  → Solution: 128-byte LCM works universally

Finding 4: Heterogeneous Scheduling = Biggest Gain
  → HeteroInfer pattern: offline solve → profile-guided placement
  → AiSystems Phase 1-2 already has Adreno/OpenCL/Vulkan/Hexagon backends
  → Missing: operator-level profiler + schedule cache

Finding 5: Layout Optimization Standard Practice
  → MNN-LLM: tiled layout 20% matmul speedup (reproducible on AiSystems)
  → ML Drift: tensor virtualization (buffer/2D/3D per kernel) on Google Pixel
  → Load-time transpose caching is proven technique
