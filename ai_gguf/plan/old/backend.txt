  Mobile GPUs are absolutely capable of running transformers. The issue is llama.cpp's scheduler architecture — it was designed for desktop 
  discrete GPUs, not mobile UMA.                                                                                                            
                                                                                                                                            
  The Proof: Other Frameworks Do It                                                                                                         
                                                                                                                                            
  - MLC-LLM — 40-60 t/s on Snapdragon 8 Gen 3 (0.5B models) using OpenCL/Vulkan                                                             
  - QNN / Qualcomm AI Engine — great performance on Hexagon NPU                                                                             
  - MediaPipe LLM — uses GPU effectively on Android with persistent buffers                                                                 
  - PowerInfer-2 — specifically designed for mobile heterogeneous computing
                                                                                                                                            
  The Fundamental Problem in llama.cpp                                                                                                      

  The ggml scheduler (ggml-backend.cpp line ~1469) does this every single token:

  for each input tensor that crosses backend boundary:
      ggml_backend_tensor_copy(input, input_cpy)  // EVERY TOKEN!

  There's no caching. Weight tensors NEVER change between tokens, but the scheduler doesn't know that. It re-copies the entire model (~229MB
   for your Q4_0) from CPU buffer to GPU buffer every single token. That's why you got 2.3 t/s — most of the time is spent copying data that
   hasn't changed.

  Desktop vs Mobile — Why n_gpu_layers Works There

  On desktop:
  n_gpu_layers=999 → weights copied to VRAM ONCE at load time
                    → GPU reads from VRAM during inference (fast, no copy)
                    → scheduler sees weights already on GPU → skips copy

  On mobile UMA:
  CPU and GPU share LPDDR5 — there IS no separate VRAM
  n_gpu_layers=0 + op_offload → scheduler copies weights EVERY token
  n_gpu_layers=999 → works but also triggers Vulkan 18s shader compile

  The 3 Specific Architecture Mismatches

  1. No concept of "same physical memory"
  On UMA, CPU pointer and GPU pointer point to the same LPDDR5 chips. The GPU can read CPU memory directly (zero-copy). But the scheduler
  doesn't know this — it sees "CPU buffer" and "GPU buffer" as separate worlds requiring copies.

  2. supports_buft is all-or-nothing
  When we tell the scheduler "I can use CPU buffers" (zero-copy), it routes ALL ops to OpenCL — not just MUL_MAT. Ops that can't handle
  host-mapped tensors crash. There's no way to say "I support host buffers ONLY for MUL_MAT."

  3. op_offload has no weight persistence
  The offload_op() API says "I want this op on GPU" but the scheduler creates a FRESH copy every graph evaluation. There's no "this is a
  constant tensor, cache the GPU copy."

  The Path Forward

  Three realistic options:

  Option A: n_gpu_layers=999 + OpenCL only (disable Vulkan)
  - Weights uploaded to OpenCL buffers ONCE at model load via set_tensor() (SoA conversion)
  - No per-token copies — scheduler sees weights already on GPU
  - Vulkan disabled → no 18s shader compile
  - All supported ops run on GPU, unsupported fall back to CPU
  - Simplest to try, most likely to work

  Option B: Custom ggml-mobile backend
  - Single backend that internally dispatches to OpenCL GPU + CPU
  - Creates CL_MEM_USE_HOST_PTR wrappers at load time (one-time, not per-token)
  - Handles its own buffer lifecycle outside the scheduler
  - Best performance but biggest effort

  Option C: Patch the scheduler
  - Add a "constant tensor" flag to ggml — scheduler caches GPU copies
  - Fixes the root cause for ALL backends
  - Upstream-friendly but requires ggml core changes
