00 What is Activation Steering? core concept
Inside every transformer layer, there is a residual stream — a vector highway of dimension d_model that flows through the entire network. Attention outputs, FFN outputs — everything is added to this stream. The key insight: concepts are directions in this high-dimensional space. "Clinical tone" is a direction. "Confident vs uncertain" is a direction. You can add a vector to the residual stream at runtime and push the model's internal representation toward any concept — no weights touched, no gradients computed.
The residual stream — what gets added at each layer
Superposition hypothesis (Elhage et al., Anthropic 2022): A model with d=4096 dimensions doesn't have 4096 features — it has millions of features packed into 4096 dims using nearly-orthogonal directions. Each concept occupies a direction, not an axis.

Consequence: Adding a vector along the "clinical language" direction adds clinical-ness to every token's representation simultaneously, without disturbing the ~million other directions that are nearly orthogonal to it. The sparsity of real activations means interference is low.
h_new[layer] = h[layer] + α · steering_vec[layer]
where steering_vec encodes a concept as a direction in ℝ^d_model
Linear Representation Hypothesis: Concepts are linearly encoded in activation space. The famous proof: in word2vec, king − man + woman ≈ queen. Same holds in LLMs — "Paris" − "France" + "Germany" ≈ "Berlin" in residual stream space.

This is WHY adding a vector works. If concepts were non-linearly encoded (e.g., in specific attention pattern configurations), you couldn't steer with a simple vector addition. The linearity is what makes steering tractable.
Hard limits of activation steering:

✗ You cannot add new factual knowledge — you can't steer toward "knowing" something the model never saw in training
✗ You cannot reliably steer at high α without degrading coherence (the model breaks)
✗ Entanglement: most concept vectors are not pure — "formal tone" correlates with "corporate/legal language"
✗ The right layer varies per concept — there's no universal answer
✗ Vectors found in Llama-3 don't transfer to Mistral — not even same-size models

What you CAN do: shift style, tone, confidence, verbosity, focus on specific domains, suppress or amplify certain behaviors — all within what the model already knows.

01 Extracting Steering Vectors step-by-step
You need a contrastive dataset: pairs of inputs that differ along exactly the dimension you want to control. For our medical assistant: "patient came in complaining of headaches" (casual) vs "patient presents with cephalgia" (clinical). Run both through the model, record the residual stream at each layer at the last token position, take the mean difference. That difference vector is the steering direction for "clinical tone." Step through the process below.

# Full steering vector extraction pipeline import torch from collections import defaultdict class ResidualStreamCapture: def __init__(self, model): self.hooks = [] self.activations = defaultdict(list) # layer → [batch acts] def register(self, model): for i, layer in enumerate(model.model.layers): h = layer.register_forward_hook( lambda mod, inp, out, idx=i: # out[0] is residual stream post-layer: [batch, seq, d_model] self.activations[idx].append(out[0][:, -1, :].detach()) ) self.hooks.append(h) def remove(self): [h.remove() for h in self.hooks]; self.hooks = [] def extract_steering_vector(model, tokenizer, pos_texts, neg_texts): capture = ResidualStreamCapture(model) capture.register(model) def get_acts(texts): acts = defaultdict(list) for text in texts: inp = tokenizer(text, return_tensors='pt').to(model.device) with torch.no_grad(): model(**inp) for layer, a in capture.activations.items(): acts[layer].append(a[-1]) # last-token act capture.activations.clear() return {l: torch.stack(v).mean(0) for l, v in acts.items()} pos_acts = get_acts(pos_texts) neg_acts = get_acts(neg_texts) capture.remove() # steering_vec[layer] is a [d_model] vector steering_vecs = { layer: (pos_acts[layer] - neg_acts[layer]) for layer in pos_acts } return steering_vecs
Layer selection matters enormously:

Early layers (0–30% of depth): surface features — punctuation, word frequency, syntax
Middle layers (30–70%): semantic content — entities, facts, domain concepts
Late layers (70–100%): task-specific — sentiment, output style, instruction-following

For our medical assistant use case — steering toward "clinical tone": target middle layers (layers 12–20 in a 32-layer model). For "formal vs casual style": target late layers (layers 24–30).

Heuristic: find the layer where the cosine similarity of the steering vector is highest with the concept's ground-truth probe. If you don't have a probe, use the layer that maximizes output consistency across 10 test prompts.
Normalisation strategies:

Raw: steering_vec = mean(pos) − mean(neg) — simplest, often works
Unit norm: steering_vec /= ||steering_vec|| — controls magnitude separately via α
PCA: take top principal component of (pos − neg) matrix — cleaner concept, less noise from paired examples
Contrastive Fisher: steering_vec = Σ_within⁻¹ · (μ_pos − μ_neg) — maximises class separation

In practice: unit-normalise and sweep α. For medical example: α=8–15 works well for clinical tone shift with minimal coherence degradation.

02 Live Injection at Runtime runtime hook
At inference time, you register a forward hook on the target layer. After each layer computes its output, you intercept the residual stream and add α × steering_vec before it flows to the next layer. The model never knows — it processes the modified representation normally. This happens every token of every generation — steering is continuous, not one-shot.

class SteeringHook: def __init__(self, model, steering_vecs, layer_ids, alpha=10.0): self.vecs = steering_vecs # {layer_id: [d_model] tensor} self.alpha = alpha self.hooks = [] self._register(model, layer_ids) def _make_hook(self, layer_id): def hook(module, input, output): hidden = output[0] # [batch, seq, d_model] vec = self.vecs[layer_id].to(hidden.device) # inject into ALL token positions (continuous steering) hidden = hidden + self.alpha * vec.unsqueeze(0).unsqueeze(0) # return modified output, keeping other outputs (attn weights, etc.) intact return (hidden,) + output[1:] return hook def _register(self, model, layer_ids): for lid in layer_ids: h = model.model.layers[lid].register_forward_hook( self._make_hook(lid) ) self.hooks.append(h) def set_alpha(self, alpha): self.alpha = alpha # change at runtime — immediate effect def remove(self): [h.remove() for h in self.hooks] self.hooks = [] # Usage steer = SteeringHook(model, clinical_vecs, layer_ids=[14, 16, 18], alpha=10.0) with torch.no_grad(): output = model.generate(input_ids, max_new_tokens=200) # fully steered steer.remove() # clean removal, model returns to baseline
Multi-layer injection: injecting at 3–5 consecutive middle layers is more stable than a single large injection. Reason: the residual stream passes through LayerNorm at each layer, which re-scales it. A single strong injection gets partially suppressed by LayerNorm. Distributing the steering across layers maintains the direction more robustly.

Formula: inject α/n at n consecutive layers starting from target_layer. For clinical tone: inject at layers 14, 16, 18 with α=4 each (equivalent effect to α=12 at one layer, but much more stable).
Per-token steering: you can change α dynamically as tokens are generated. For example:

• Amplify steering only when generating clinical terminology (detect via logit distribution)
• Reduce steering near punctuation to preserve natural sentence rhythm
• Ramp up steering at the start of response, taper toward end

def dynamic_alpha_hook(module, input, output): token_probs = get_last_token_probs() # peek at logits # increase α if model is drifting away from target domain drift = cosine_dist(output[0][:,-1,:], target_centroid) alpha = base_alpha * (1 + drift * gain_factor) return steer(output, alpha)

03 Surgical Head-Level Targeting precision
Instead of steering the full residual stream, you can target specific attention heads. Each head produces an output of dimension d_head that contributes to the residual. By zeroing or scaling specific head outputs, you can suppress behaviors associated with those heads — without affecting others.

This requires a calibration step: identify which heads are "responsible" for the behavior you want to change. Click heads below to see their simulated contribution.
Head contribution map — click heads to ablate (zero out)
Causal tracing (Meng et al. 2022 — ROME): a two-step process to find which heads "cause" a behavior:

1. Corrupt run: add Gaussian noise to input embeddings → get corrupted output
2. Restore run: run the corrupted model but restore (patch) the clean activation at one specific site (head, layer) at a time

If restoring head (l, h) recovers the correct output → that head is causally important for that behavior. Repeat for all heads. Build an importance map.

For our medical assistant: run causal tracing on "clinical vs casual" pairs → identify the 5–8 heads that most strongly encode the formality distinction.
DRESS (NeurIPS 2024): style editing via attention head subspace manipulation. Steps:

1. Find style subspace: collect style-contrasting pairs → PCA on head output differences → top-k principal components define the "style subspace" for that head
2. Project out: remove the style direction from each head's output: out_edited = out - (out · ŝ)ŝ + target_style · ŝ
3. Adaptive scaling: scale the edit based on how much that head "contributed" to the style in calibration

Result: zero-shot style transfer (formal↔casual, english↔chinese formality registers) with better semantic preservation than full activation steering.
# Head-level ablation / steering class HeadSteering: def __init__(self, model, target_heads, mode='ablate'): # target_heads: list of (layer, head) tuples self.heads = target_heads self.mode = mode # 'ablate' | 'scale' | 'steer' self.scale = 0.0 # 0 = full ablation self.hooks = [] def _hook(self, layer_idx, head_indices): def h(module, inp, out): # out[0]: [batch, seq, n_heads * d_head] B, S, _ = out[0].shape d_head = module.head_dim n_heads = module.num_heads attn = out[0].view(B, S, n_heads, d_head) for hi in head_indices: attn[:, :, hi, :] *= self.scale # ablate or scale return (attn.view(B, S, -1),) + out[1:] return h def register(self, model): # Group heads by layer by_layer = defaultdict(list) for (l, h) in self.heads: by_layer[l].append(h) for l, heads in by_layer.items(): hook = model.model.layers[l].self_attn.register_forward_hook( self._hook(l, heads) ) self.hooks.append(hook)

04 Can Weights Actually Update at Runtime? the hard question
Yes — but with major constraints. Standard deployment freezes all weights. To update weights, you need: (1) a forward pass to compute outputs, (2) a loss signal to measure error, (3) a backward pass to compute gradients, and (4) an optimizer step to update weights. All four are possible on edge devices — but memory and compute explode. The chart below shows what's actually feasible on real hardware.

Gradient memory = ~2× model memory (FP32 grads of FP16 weights). Optimizer state (Adam = 2 momentum terms) = another 2×. Total: ~6× inference memory for full training. A Raspberry Pi has 4–8GB RAM. An iPhone 15 Pro has 8GB. Conclusion: full backprop on any model >1B is borderline impossible on consumer edge devices without gradient checkpointing + partial layer training.
What breaks during runtime weight update:

1. Catastrophic forgetting: 1–10 gradient steps on new data can overwrite what the model knew. A medical assistant that learns 5 corrections could forget how to spell.

2. Quantization incompatibility: Edge models run INT4/INT8. Gradient math requires FP32. You must dequantize → update → requantize. Rounding error accumulates per step.

3. Thermal throttling: backward pass on a mobile NPU generates heat → device throttles → next forward pass is slower → user experience degrades

4. No training infrastructure: production inference runtimes (llama.cpp, TFLite, ONNX Runtime) don't expose gradient computation. You'd need PyTorch or MLX with autograd.
Forward-only learning (2024): Amazon researchers showed you can fine-tune vision-language models using only forward passes — no backprop. Uses perturbation theory: perturb weights slightly, measure output change, estimate gradient from finite differences.

Cost: 2× forward passes per "gradient" estimate (one base, one perturbed). Memory: same as inference. No autograd needed.

Viable for: models up to ~7B on devices with ≥4GB RAM. Quality: ~7% below standard backprop fine-tuning. But for 10 domain corrections — close enough.

05 Fast Weights & Test-Time Training paradigm shift
The cleanest solution: instead of fighting against frozen weights, design the architecture to have two kinds of weights. Slow weights — frozen, trained offline. Fast weights — a small subnetwork that updates during inference via a self-supervised loss on the current context. The fast weights are the model's "scratchpad memory" that adapts in real time.

This is Test-Time Training (TTT). The fast weight update is lightweight enough to run during token generation.
Two-speed architecture — click to simulate one TTT step
steps: 0
θ_fast_new = θ_fast − η · ∇_θ_fast L_self(x_t)
where L_self = next-token prediction loss on context chunk
At each token (or chunk of tokens), the TTT inner loop performs:

1. Self-supervised loss: predict the next token from the current context using only the fast MLP weights as the memory.
2. 1–3 gradient steps: update the fast weights to reduce this loss.
3. Forward pass: use the updated fast weights to produce the output for the current token.

The slow Transformer weights handle syntax, world knowledge, instruction following. The fast MLP weights store the compressed "gist" of what the model has read so far — replacing the KV cache entirely.

Key insight: for our medical assistant — as it reads the patient file, the fast weights compress and memorize it. No matter how long the file, the fast weights are always a fixed size (e.g., 512×512 matrix = 262K parameters).
TTT-E2E (NVIDIA/Stanford, Dec 2025): the key improvement over earlier TTT is making the training loop end-to-end — the meta-learning at training time explicitly optimizes for fast adaptation at test time (MAML-style double loop).

Result: 3B parameter TTT-E2E model matches full-attention Transformer quality at 128K context, while running at constant latency regardless of context length — 2.7× faster than full attention at 128K, 35× faster at 2M tokens.

For edge: a 125M parameter TTT-E2E model could maintain a "memory" of everything it's processed on-device, in a fixed-size fast-weight state. The slow weights are frozen (inference-only). Only the fast weights update — they're tiny (~1M parameters).
class TTTLayer(nn.Module): def __init__(self, d_model, fast_hidden=256): super().__init__() # Slow weights — frozen at inference self.W_q = nn.Linear(d_model, d_model) # standard QKV projections self.W_k = nn.Linear(d_model, d_model) self.W_v = nn.Linear(d_model, d_model) # Fast weights — the tiny updatable memory MLP self.fast_w1 = nn.Parameter(torch.randn(d_model, fast_hidden) * 0.01) self.fast_w2 = nn.Parameter(torch.randn(fast_hidden, d_model) * 0.01) self.eta = 0.01 # inner loop learning rate def forward(self, x): # self-supervised loss: predict x[t] from x[:t] via fast weights pred = torch.relu(x @ self.fast_w1) @ self.fast_w2 loss = F.mse_loss(pred[:, :-1], x[:, 1:].detach()) # update fast weights (1 gradient step in-place) grad_w1, grad_w2 = torch.autograd.grad(loss, [self.fast_w1, self.fast_w2]) self.fast_w1.data -= self.eta * grad_w1 self.fast_w2.data -= self.eta * grad_w2 # produce output using updated fast weights + standard attention mem = torch.relu(x @ self.fast_w1) @ self.fast_w2 return x + mem # add to residual stream

06 LoRA as a Live Adapter — Hot-Swap Weight Updates production viable
LoRA decomposes a weight update ΔW into two small matrices: ΔW = A · B where A ∈ ℝ^(d×r) and B ∈ ℝ^(r×d), rank r << d. For a 4096×4096 weight matrix: full update = 16M parameters. LoRA r=8: 65K parameters — 256× smaller. These small matrices live on top of the frozen base model and can be updated, swapped, and loaded at runtime with almost no memory overhead.

# On-device LoRA training loop — minimal memory footprint class EdgeLoRAAdapter: def __init__(self, model, target_modules, rank=4, alpha=8): self.adapters = {} self.scale = alpha / rank for name, module in model.named_modules(): if any(t in name for t in target_modules): d_in, d_out = module.weight.shape # Freeze base weights module.weight.requires_grad = False # Add LoRA matrices (only these get gradients) A = nn.Parameter(torch.randn(d_in, rank) * 0.02) B = nn.Parameter(torch.zeros(rank, d_out)) self.adapters[name] = (A, B, module) def learn_from_correction(self, input_text, target_text, steps=3): # Doctor corrects: "headache" → "cephalgia" optimizer = torch.optim.SGD( [p for (A, B, _) in self.adapters.values() for p in [A, B]], lr=5e-4 ) for _ in range(steps): # 3 steps = fast, low forgetting risk self._inject_adapters() loss = cross_entropy_loss(model(input_text), target_text) loss.backward() # only flows to A,B matrices (64K params, not 7B) optimizer.step() optimizer.zero_grad() self._detach_adapters() def save(self, path): # Save ONLY adapter weights — ~250KB for rank=4, not 14GB torch.save({n: (A.data, B.data) for n,(A,B,_) in self.adapters.items()}, path)
Gradient checkpointing: during backprop, normally all activations are kept in memory (one per layer per token). For a 32-layer model at seq=512: 32 × 512 × 4096 × 4 bytes ≈ 256MB of activations just for the forward pass.

Gradient checkpointing discards intermediate activations and recomputes them on demand during backprop. Memory reduction: ~8×. Cost: ~30% more compute (each activation recomputed once). Net result: training a 1B LoRA r=4 requires only ~800MB RAM peak — fits on an iPhone 15 Pro.
Memory(checkpoint) ≈ O(√n) layers kept
vs Memory(standard) ≈ O(n) layers kept
QLoRA on edge: Dettmers et al. showed you can keep base model in INT4/INT8, and only the LoRA matrices A,B in FP16/FP32. Since A and B are tiny, this adds negligible memory. Gradient flows through the dequantize operation (straight-through estimator) into A,B only.

For our medical assistant: 7B model in INT4 = 3.5GB. LoRA r=4 adapters = 50MB. Total RAM for on-device fine-tuning with gradient checkpointing: ~5GB peak. Just fits on a modern iPhone or high-end Android. Jetson Nano (4GB) can do 1B QLoRA updates in real-time.

07 Meta-Learning: Teaching the Model to Learn Fast MAML + inner loop
The problem with naive runtime weight updates: the model wasn't trained to update itself efficiently. 3 SGD steps may help on one thing and break 10 others. Meta-learning solves this by training the model's initialization to be "fast-adaptable" — close to the optimal parameters for any task after just 1–3 gradient steps.

MAML (Finn et al. 2017): train θ such that θ + 1 gradient step → task-optimal. The outer loop minimises the post-adaptation loss across all tasks. The model learns to be good at learning, not just good at tasks.
MAML two-loop training — outer loop (meta) + inner loop (task adaptation)
θ* = argmin_θ Σ_task E[ L(θ − α∇L(θ, D_support), D_query) ]
outer loop: θ ← θ − β∇_θ [post-adaptation loss]
MAML requires second-order gradients: gradients of gradients. This is expensive (2× memory, 2× compute for the backward pass). For LLMs, this means MAML pretraining is ~3× slower than standard pretraining.

But once trained — at inference, you only need the inner loop: 1–3 gradient steps on a handful of examples. These steps are cheap, fast, and reliable because the model's initialization was specifically optimized to be in a fast-adaptation regime.
FOMAML (First-Order MAML): ignore the second-order terms. Approximate the meta-gradient as just the first-order gradient at the adapted parameters. 2× cheaper. 90% of MAML quality.

Reptile (OpenAI 2018): even simpler — no explicit meta-gradient. Just take multiple SGD steps on each task and move θ toward the task-adapted parameters:
θ ← θ + ε(θ_task_adapted − θ)
No second-order computation at all. Reptile works well for adaptation tasks like domain shift — ideal for our edge medical assistant.
In-Place TTT (OpenReview 2025): a plug-in that adds TTT ability to any existing LLM without retraining from scratch. Key innovation: treats the final projection matrix of MLP blocks as the fast weights. Only these matrices update during inference — everything else is frozen.

Why the MLP output projection? FFN layers are "key-value memory" (Geva et al. 2021) — they store factual associations. The output projection maps the retrieved memory to the output space. Updating it at runtime allows the model to "add" new associations without touching the attention mechanism or embedding space.

09 Full Controlled Runtime Architecture production blueprint
Putting it all together: a complete runtime that supports activation steering (zero overhead), LoRA hot-swap updates (low overhead), and optional TTT fast-weight updates (medium overhead). All three can coexist in the same runtime. The key: each layer is a pipeline — base forward → hook interception → activation patch → adapter delta → output. Each stage can be enabled/disabled independently.
Full runtime pipeline — click any stage
class EdgeRuntimeController: """ Full runtime that combines: 1. Activation steering (zero overhead — just vector addition) 2. LoRA adapters (hot-swappable, ~50KB overhead) 3. TTT fast weights (optional, small gradient at each step) """ def __init__(self, model, config): self.model = model self.steering = SteeringHook(model, {}, [], alpha=0) self.lora = EdgeLoRAAdapter(model, config.lora_modules, rank=config.rank) self.ttt = TTTLayer(config.d_model) if config.use_ttt else None self.memory_guard = MemoryGuard(max_mb=config.max_memory_mb) def set_concept(self, steering_vecs, alpha=10.0, layers=None): # Zero-overhead steering — just replace hook vectors self.steering.remove() self.steering = SteeringHook(self.model, steering_vecs, layers or [14,16,18], alpha) def learn(self, input_text, target_text): # LoRA weight update from a correction if self.memory_guard.safe(): self.lora.learn_from_correction(input_text, target_text, steps=3) else: # Fall back to steering-only if memory is low self.update_steering_from_example(input_text, target_text) def generate(self, prompt, **kwargs): with self.memory_guard: return self.model.generate( prompt, hooks=self.steering, adapters=self.lora, **kwargs ) def save_state(self, path): # Save ONLY deltas — steering vecs (~64KB), LoRA (~250KB), TTT (~1MB) # Never re-save the 7GB base model torch.save({ 'steering_vecs': self.steering.vecs, 'lora_adapters': self.lora.get_state_dict(), 'ttt_weights': self.ttt.state_dict() if self.ttt else None }, path) # total: ~1.3MB vs 14GB full checkpoint
Critical safety guards you MUST implement:

1. Forgetting detector: evaluate on a held-out set after each LoRA update. If perplexity on base tasks rises >5%, roll back the update.
2. Steering coherence check: after steering, run a 20-token sample. If entropy is very low (model collapsed to one token) or very high (incoherence), reduce α by half.
3. Memory watchdog: monitor RSS memory every 10 tokens. If approaching device limit, disable gradient-based updates and fall back to steering-only.
4. Update rate limiter: cap LoRA updates at N per hour to prevent adversarial inputs from steering the model in harmful directions through repeated corrections.
5. Ephemeral mode: for privacy-sensitive domains, run all weight updates in a session-scoped RAM buffer. On session end, discard all deltas — base model untouched.
Persistence strategy — what to save vs discard:

Steering vectors: 32 layers × 4096 dims × 4 bytes = 512KB per concept. Store dozens on-device.
LoRA adapters: 2 matrices × 4096 × r=8 × 4 bytes × 32 layers ≈ 8MB per fine-tuned persona. Store multiple user profiles.
TTT fast weights: 512×512 per TTT layer × ~8 TTT layers ≈ 16MB per context session.

Total personalisation state for our medical assistant: steering vecs (5 concepts) + LoRA adapters (doctor's style) + session TTT = ~30MB. The base model stays as a single shared 7GB file. Multiple users can have different 30MB personalisation packs on the same device.
