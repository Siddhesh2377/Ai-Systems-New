  What MORE Can We Modify in llama.cpp?

  Your document dynamic-weight-runtime.md maps out the full hierarchy. Here's what's left and whether it's feasible:

  Level 1 — Still Within Transformer (Bolt-On Modifications)

  1. RoPE Position Manipulation — Already supported via hparams, but we could do more:
  - Position offset injection: Shift token positions to make the model "think" certain tokens are closer/further. E.g., make persona tokens
  appear at position 0 (always "recent") regardless of actual position.
  - Per-head RoPE frequency scaling: Different heads get different position sensitivity. Some heads attend locally (high freq RoPE), others
  globally (low freq).
  - Implementation: Modify build_rope() in llama-graph.cpp to accept per-head frequency multipliers.

  2. Embedding Space Injection (Soft Prompts) — Point [1] in our diagram:
  - Instead of text tokens, inject learned continuous vectors directly into the embedding layer
  - Like "prompt tuning" (Lester et al. 2021) but at runtime
  - We could store per-persona embedding vectors (~4KB each) and prepend them
  - Implementation: Add virtual tokens before the real tokens, fill with learned embeddings

  3. FFN Gating / Mixture-of-Experts Style Routing:
  - The FFN in each layer has gate, up, and down projections
  - We could add a persona-conditional gate that routes activations differently based on personality
  - Implementation: Multiply FFN gate by a learned persona vector before the activation function

  4. LayerNorm Affine Shift:
  - Every layer has a LayerNorm with learned γ (scale) and β (bias)
  - We could add per-persona offsets to γ and β, shifting the normalization
  - This is extremely cheap (one add per element) and surprisingly effective
  - Research: "StyleAdapter" (2024) showed LayerNorm shift alone can do style transfer

  Level 2 — Beyond Transformer (What Your Document Covers)

  These are the modifications from dynamic-weight-runtime.md that go beyond the standard transformer:

  5. Fast Weight Memory (IMPLEMENTED) — System F:
  - W_fast = γ·W_fast + η·h⊗h — Hopfield write rule
  - Gives the model conversation memory in a fixed-size matrix
  - Unlike KV cache: doesn't grow with context, naturally decays old info

  6. Hypernetwork-Style Weight Generation:
  - A small MLP that takes the conversation context embedding and generates LoRA-style delta matrices for each layer
  - W_effective = W_base + A(context)·B(context) where A,B are generated per-context
  - This means the model's weights literally change based on what it's talking about
  - Feasible in llama.cpp: We can pre-compute the context embedding (from our captured activations), run a small MLP (stored as a few weight
   matrices), and apply the result as an adapter
  - Cost: One small MLP forward pass (~100K params) per generation turn, not per token

  7. Dynamic Sparse Masks:
  - W_effective = W ⊙ M(t) — binary mask that changes at runtime
  - Prune weak connections, grow new ones based on activation co-occurrence (Hebbian)
  - The weights are always in memory (GGUF file), we just mask which ones participate
  - Feasible: Sparse matrix operations are actually MORE efficient on mobile (less computation)
  - Challenge: Need to track co-activation statistics during generation

  8. KAN-Style Learnable Activations:
  - Replace fixed ReLU/GeLU with per-edge learnable spline functions
  - Each connection has its own activation curve, stored as B-spline coefficients
  - NOT feasible with pre-trained transformers — requires a KAN-trained model
