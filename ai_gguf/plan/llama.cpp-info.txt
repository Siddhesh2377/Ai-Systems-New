  Complete llama.cpp Function Audit: Desktop vs Android vs Hybrid

  Legend

  - DESKTOP = Tuned for discrete GPU / high RAM / x86
  - ANDROID = Tuned for mobile UMA / ARM / power-constrained
  - HYBRID = Works on both, no clear bias
  - UNKNOWN = No clear optimization target

  The Big Picture

  DESKTOP-TUNED (the problems):
  ├── ggml scheduler         ← copies weights EVERY token (kills perf)
  ├── thread pool poll=50    ← battery drain
  ├── 512 max threads        ← wasted memory
  ├── gallocr SIZE_MAX       ← assumes unlimited virtual memory
  ├── 4-copy pipeline        ← 2GB overhead on mobile
  ├── OpenCL profiling       ← forces sync execution
  ├── OpenCL 377MB prealloc  ← exceeds mobile GPU budget
  ├── supports_buft = false  ← ROOT CAUSE of weight copies
  ├── x86 AVX/AVX-512/AMX   ← dead code on Android
  ├── Vulkan training ops    ← dead code on Android
  └── NUMA thread pinning    ← irrelevant on mobile

  ANDROID-TUNED (your work):
  ├── Op-type dispatch (MUL_MAT→NPU, FLASH_ATTN→GPU)
  ├── fd-based model loading (Android SAF)
  ├── OpenCL USE_HOST_PTR zero-copy
  ├── Adreno kernel specialization
  ├── Runtime GEMV for arbitrary dimensions
  ├── Vulkan mobile GPU detection
  ├── Vulkan UMA memcpy optimization
  ├── F16 KV cache default
  ├── Flash attention per-layer
  ├── Hexagon backend (pure mobile)
  ├── Thermal monitoring
  └── Kernel/pipeline caching

  HYBRID (works on both):
  ├── Memory alignment (16B = correct for ARM + x86)
  ├── Graph allocator (dependency tracking)
  ├── Batch processing
  ├── Sampling algorithms
  ├── Chat templates
  ├── KV cache management
  └── Tensor layout/strides

  The single biggest problem is supports_buft() returning false for host buffers — this one function causes the scheduler to copy every
  weight every token on UMA devices. Everything else is either already Android-tuned or is dead code that can be stripped.
